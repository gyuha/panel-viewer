# 한장 모드 `화면에 맞추기`가 저해상도 이미지를 확대하지 않는 문제

## 목표 / 비목표

- **목표**: 한장 모드 `화면에 맞추기`에서 뷰어 영역보다 작은 이미지도 **폭·높이 중 먼저 닿는 쪽까지 확대**되게 한다. 비율은 유지하고 이미지 전체가 보인다.

- **비목표**:
  - **연속 모드 `폭 맞추기`는 건드리지 않는다.** `.cont-img`의 `max-width: 900px` 때문에 창 폭과 무관하게 최대 900px로만 표시되는 같은 부류의 문제가 있으나(`git log -S`로 확인: 최초 커밋 `f7bf594`부터 있었고 근거 기록 없음), 걷어내면 **저해상도 파일만이 아니라 지금 잘 보던 모든 파일의 읽기 폭이 바뀐다.** 영향 범위가 자릿수로 달라 검증 기준이 흐려진다. → 별도 태스크("연속 모드의 읽기 폭을 어떻게 정할지")로 남김.
  - **확대 상한을 두지 않는다.** 1.6배 확대는 Retina에서 실질 3배 보간이라 스캔 글씨가 뭉개지지만, 상한을 두면 "맞추기인데 여전히 안 찬다"는 중간 상태가 생긴다. 선명하게 보고 싶을 때 쓸 선택지는 **`원본`이 이미 담당한다.**
  - **설정 옵션을 추가하지 않는다** (확대 여부 토글 등). 요청 범위 밖.
  - **`image-rendering`을 바꾸지 않는다.** 확대된 선화는 기본값(부드러운 보간)이 nearest-neighbor보다 낫다.
  - **고해상도 이미지의 표시 결과를 바꾸지 않는다** — 이것은 부수 효과가 아니라 요구사항이다(회귀 금지).

## 근거 문서

- **용어집**: `.forge/CONTEXT.md`의 **이미지 맞춤**(이번 그릴링에서 신규 추가 — "맞추기는 축소만이 아니라 확대도 포함한다"가 이 태스크가 확정한 의미) · **보기 모드**.
- **관련 ADR**: 없음. CSS 속성 3개 변경으로 되돌리기가 자유롭고, 트레이드오프도 그릴링에서 정리된 수준이라 ADR 기준 미달.
- **완료 정의**: 한장 모드 `화면에 맞추기`에서 984×739 이미지가 스테이지 폭에 꽉 차게 표시되고, 고해상도 파일은 수정 전과 동일하게 보인다.

## 진단 (측정값 — 추측 아님)

`App.css`의 base 규칙이 `fit-screen`에 그대로 쓰인다:

```css
.viewer-page { max-width: 100%; max-height: 100%; width: auto; height: auto; object-fit: contain; }
```

`max-*`는 **큰 이미지를 줄이기만** 하고 `width/height: auto`는 작은 이미지를 자연 크기로 둔다 → 확대가 일어나지 않는다.

측정: 이미지 **984×739**(은혼-001.cbz), 창 **1605×1287**(영속 상태 `windowSize`), 스테이지 ≈ **1573×1211**(툴바 44px + 패딩 16×2 제외, 파일 패널 숨김 기준). `contain` 배율 = `min(1573/984, 1211/739)` = `min(1.60, 1.64)` = **1.60배(폭 제약)**.

부작용으로 **`화면에 맞추기`가 저해상도에서 `원본`과 완전히 동일하게 동작한다** — 서로 다른 두 옵션이 같게 동작하는 것 자체가 결함이고, 사용자에게는 "눌러도 아무 일이 없다"로 보인다.

## 작업 슬라이스

- [ ] **S1. base `.viewer-page` 규칙의 `width`/`height`를 `100%`로 바꾼다.**
  ```css
  width: 100%; height: 100%;   /* auto → 100%, max-*와 object-fit: contain은 유지 */
  ```
  이미지 박스가 스테이지를 채우고 `object-fit: contain`이 비율을 지키며 축소·**확대** 모두 처리한다. flex 중앙 정렬은 무의미해지지만 `contain`이 중앙 배치를 대신하므로 결과는 같다. 주석("기본(fit-screen)은 위 기본 규칙 그대로")도 그대로 유효하다.

  **base만 고쳐도 안전한 근거**: `fit-width`(`App.css:781`)·`fit-height`(`:788`)·`fit-original`(`:795`)이 base가 설정하는 `width`·`height`·`max-width`·`max-height`·`object-fit`을 **전부 덮어쓴다.** 따라서 이 변경은 `fit-screen`에만 도달한다. 별도 `.fit-screen` 규칙을 새로 만들 필요 없음.

  **회귀 위험 없음을 확인한 것**: `click-zone`은 `position: absolute`라 이미지 박스 크기와 무관하다(`App.css:804`).

  — 완료 기준: `task dev`에서 **(a)** 은혼-001.cbz(984×739)를 한장 `화면에 맞추기`로 열면 이미지가 스테이지 폭에 꽉 차고 위아래 여백이 사라진다(비율 유지, 잘림 없음). **(b)** 원피스-002.cbz(고해상도)를 같은 설정으로 열면 수정 전과 크기·위치가 동일하다. **(c)** `원본`·`폭 맞추기`·`높이 맞추기` 세 옵션이 수정 전과 동일하게 동작한다.

## 검증 메모

CSS만 바뀌므로 자동 테스트로는 잡히지 않는다 — `vitest.config.ts`에 `css` 옵션이 없어(기본 `css: false`) 테스트 실행 중 스타일시트가 처리되지 않고, jsdom에는 레이아웃 엔진이 없어 백분율·`object-fit` 계산이 관측 불가하다. TS 파일은 한 줄도 바뀌지 않으므로 새 순수 로직도 없다. 위 완료 기준 (a)(b)(c)를 눈으로 확인하는 것이 이 태스크의 검증이다.
