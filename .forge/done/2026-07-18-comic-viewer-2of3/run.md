# RUN — 보기 모드 완성 + 상태 기억 (comic-viewer-2of3)

## 계획대로 된 것
- **S1 우→좌 페이지 모드**: `nav.ts`에 방향 인지 `arrowAdvance(key, page, count, mode)` 추가 — 좌→우는 오른쪽=다음, 우→좌는 왼쪽=다음. `PageView`가 키/클릭 매핑을 모드에 따라 반전. Vitest로 양 모드 검증.
- **S2 연속 스크롤 모드**: `ContinuousView` — 세로로 페이지를 쌓고 폭 맞춤(max 900px). 오프스크린 이미지는 네이티브 `loading="lazy"` + `decoding="async"`로 지연 로드해 대용량에서 한꺼번에 로드되지 않음.
- **S3 모드 전환 UI + 페이지 동기화**: 툴바에 3-모드 토글. 연속 뷰는 `key`로 모드 전환 시 재마운트되어 마운트 시점의 현재 페이지로 `scrollIntoView`, IntersectionObserver로 스크롤 중 최상단 가시 페이지를 현재 페이지로 갱신 → 페이지↔연속 전환 시 위치 유지.
- **S4 상태 기억(TDD)**: `state.rs` — 파일별 읽던 위치(경로→페이지 맵) + 보기 모드 + 마지막 폴더를 앱 데이터 디렉터리 `state.json`으로 저장/복원. cargo 테스트 4개 그린(왕복·미존재→기본값·손상→기본값·모드 소문자 직렬화). 커맨드 `load_state`/`save_reading_position`/`save_view_mode`/`save_last_folder`를 setup에서 로드한 스토어에 연결. App이 시작 시 복원, 열 때 해당 파일의 읽던 위치에서 시작, 페이지 변경은 400ms 디바운스 저장.

## 계획과 달라진 점 / 현장 결정
- **연속 스크롤 가상화 = 네이티브 lazy 로딩**으로 구현(전용 가상 스크롤러 대신). MVP엔 충분하나 미로드 페이지 높이 미상으로 먼 페이지로의 정확한 점프는 근사 — `cont-page`에 `min-height: 60vh` 플레이스홀더로 스크롤 위치를 근사 보정. 정밀 가상화는 후속 여지.
- **연속 모드 키보드 스크롤**은 네이티브에 의존(휠/트랙패드 우선). 컨테이너 포커스 없이는 Space/화살표 스크롤이 제한적일 수 있음 — 대용량 읽기의 핵심인 휠 스크롤엔 영향 없음.
- `last_folder` 저장 커맨드는 배선했으나 폴더 탐색 UI는 part 3라 아직 호출부 없음(part 3에서 사용).

## 검증 범위 (중요)
- **기계 검증됨**: cargo test 10(archive 6 + state 4) · vitest 6(좌→우/우→좌 nav) · `tsc && vite build` · `cargo build` 모두 그린.
- **기계 검증 불가 → 사용자 수동 확인 필요**: 세 모드 실제 전환 시 페이지 유지, 앱 재시작 후 읽던 위치·보기 모드 복원, 연속 스크롤 실제 동작·메모리. `npm run tauri dev`로 확인 권장.
